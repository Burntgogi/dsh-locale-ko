# @deepseek-ai/dsh-experimental-liveshare

[English](README.md) | [中文](README.zh.md) | 한국어

## 개요

일반 DSH 브라우저 화면을 통해 동료와 세션을 공유합니다. 소유자는 보기 또는 제한된 쓰기를 선택하고 분기 허용 여부를 별도로 정하며, 소유자 호스트가 이 선택을 적용합니다. 첨부파일 업로드는 공유 자체에 따릅니다. 열람자가 볼 수 있는 세션은 파일을 받을 수 있습니다. 이 선택형 번들은 소유자 로그인, 공유 제어, 발신 게이트웨이와 소유자 자신의 웹 페이지에 열람자 화면을 추가합니다. 기본 웹 프로필에는 포함되지 않습니다. 별도로 배포되는 Liveshare 서버가 열람자를 인증하고 요청을 전달하며, 그 OAuth, 데이터베이스, 라우팅 및 배포 구현은 이 패키지에 속하지 않습니다.

## 이 패키지 사용

### 프로필과 빌드 요구 사항

매니페스트는 설치 가능한 `dsh.bundle` 계층과 브라우저 화면을 선언합니다. [기본 표시와 활성화](#default-visibility-and-enabling)에 설명한 대로 프로필에서 활성화할 때까지 번들은 숨겨져 있습니다. 지원되는 애플리케이션은 여전히 `dsh --profile`로 시작합니다.

소유자, 열람자와 Liveshare 서버는 일치하는 프로토콜 버전을 사용해야 합니다. 빌드에는 소유자의 게이트웨이 프로세스가 포함되며 열람자 페이지에는 별도 빌드가 없습니다. 패키지 버전, 내보내기 및 게시 내용은 [package.json](package.json)에 선언되어 있습니다.

<a id="default-visibility-and-enabling"></a>

### 기본 표시와 활성화

dsh 설치에는 이 패키지가 런타임 의존성으로 포함되지만, 제공되는 프로필 중 이 번들을 선택하는 것은 없습니다. 따라서 플러그인이 실행되지 않고 플러그인 관리자의 **내장 플러그인 설정**이나 **실험용 플러그인들**, **더 보기** 페이지에도 표시되지 않습니다. 번들 ID로는 계속 접근할 수 있으므로 ID로 번들을 여는 페이지에서는 상세 정보를 볼 수 있습니다.

활성 프로필의 패치 파일 `$DSH_HOME/profiles/<profile>/cordis.patch.yml`에 두 항목을 삽입하여 활성화합니다. 이 파일은 Loader 패치로 된 하나의 YAML 시퀀스입니다. 다음은 번들 자체의 [패치](cordis.patch.yml)가 삽입하는 항목이며 `!!js` 표현식을 사용할 수 있습니다.

```yaml
- insert:
    - id: liveshare-viewer-declarations
      name: '@deepseek-ai/dsh-experimental-liveshare/viewer-declarations'
    - id: liveshare-share-host
      name: '@deepseek-ai/dsh-experimental-liveshare'
      config:
        ownerIdentityProvider: <provider-id>
        ownerIdentityTenant: <tenant-id>
        ownerIdentitySubject: <subject-id>
        allowedSubjectIds: []
        ownerStateFile: /path/to/owner-shares.json
```

각 `<...>` 자리표시자를 해당 배포 환경의 값으로 바꾸세요. ID 제공자, 테넌트와 주체는 Liveshare 서버 배포에 설정된 값이며 예시 값은 실제 ID가 아닌 자리표시자입니다. 환경 계층도 사용할 수 있습니다. `$DSH_HOME/.env`에 `LIVESHARE_*`를 설정하고 번들 자체의 `!!js process.env.…` 표현식을 유지하세요. Liveshare 서버 주소는 이 설정에 포함되지 않습니다. 아래 소유자 설정에서 설명하듯 소유자가 처음 사용할 때 공유 대화상자에 입력합니다.

패치 대신 프로필에서 번들을 선택할 수도 있습니다. `$DSH_HOME/profiles/<profile>/package.json`의 `dsh.profile.bundles`에 `"@deepseek-ai/dsh-experimental-liveshare"`를 추가하세요. 카드가 목록에 표시된 뒤 카드의 스위치를 사용하면 이 항목이 기록됩니다.

두 방법 모두 재구성할 때만 적용됩니다. 프로필의 HMR 행이 활성화된 경우 프로필을 다시 읽을 때 적용되고, 그렇지 않으면 다음 `dsh` 시작 시 적용됩니다. 번들이 선언한 행 중 하나 이상이 실행되면 카드가 **실험용 플러그인들**과 **더 보기** 페이지에 나타납니다. 항목을 제거하거나 비활성화하거나 `dsh.profile.bundles`에서 번들을 제거하면 해당 행이 중지되고 카드가 두 목록에서 사라집니다.

### 소유자 설정

| 변수 | 기본값 | 의미 |
|---|---|---|
| `LIVESHARE_OWNER_PROVIDER_ID` / `LIVESHARE_OWNER_TENANT_ID` / `LIVESHARE_OWNER_SUBJECT_ID` | 미설정 | 기존 주체 일치에 사용하는 소유자 ID. 서버가 발급한 자격 증명을 대체하지 않음 |
| `LIVESHARE_OWNER_DISPLAY_NAME` | 미설정 | 설정된 ID의 표시 이름 |
| `LIVESHARE_ALLOWED_SUBJECTS` | 비어 있음 | 공유의 접근 규칙에 추가되는 배포 전체 주체 허용 목록 |
| `LIVESHARE_OWNER_STATE_FILE` | `$DSH_HOME/liveshare/owner-shares.json` | 저장된 공유 메타데이터, Liveshare 서버 주소, 인스턴스 ID 및 관리 토큰 |
| `LIVESHARE_OWNER_CREDENTIAL_FILE` | 상태 파일 옆의 `owner-credential.json` | 발급한 Liveshare 서버에 연결된 저장 자격 증명 |

Liveshare 서버 주소는 처음 사용할 때 설정합니다. 공유 대화상자의 주소 필드에 입력하고 저장하세요. 주소는 소유자 상태 파일에 유지되며 이후 공유가 해당 주소로 게시됩니다. 이미 등록을 기다리는 게시 요청은 등록 정보, 저장 기록 및 반환 링크에 처음 서버 주소를 유지하고 기존 공유도 기록된 Liveshare 서버 주소를 유지합니다. 공유 관리 Remote로 저장 주소를 지우면 호스트에 주소가 없게 되며, 공유를 만들 때 주소를 저장해야 한다는 메시지가 표시됩니다. 배포 값으로 대체되지 않습니다. 열람자가 공유 옆에서 보는 이름은 Relay가 검증한 자격 증명의 표시 이름이며 로컬 설정으로 덮어쓸 수 없습니다. 주체만 담은 자격 증명은 그 주체의 레이블을 표시합니다. 제공자 애플리케이션 비밀은 이 설정이 아닌 Liveshare 서버에 속합니다.

### 로그인과 공유 관리

공유 대화상자는 소유자에서 짧은 수명의 인증 트랜잭션을 시작합니다. 팝업은 예상된 창, 출처 및 트랜잭션에만 일회용 코드를 반환합니다. 소유자는 비공개 검증자로 코드를 교환하고 해당 Liveshare 서버에 연결된 자격 증명을 저장합니다. 일반 브라우저 로그인 흐름은 자격 증명을 브라우저 저장소나 URL에 저장하지 않습니다. 만료, 취소, 재사용 또는 불일치 트랜잭션은 안전하게 거부됩니다. 코드 교환 중 Liveshare 서버가 바뀌면 다시 원래대로 바뀐 경우에도 자격 증명을 저장하기 전에 로그인이 거부됩니다. 저장이 완료된 후 검사와 공유 클레임은 해당 작업의 Liveshare 서버 및 자격 증명 ID를 유지합니다. Liveshare 서버가 ID 연결을 지원하지 않는 경우를 포함해 검증된 ID 없는 게시는 거부됩니다.

공유 관리는 `liveshareShares` Typert Remote가 담당합니다. 공유 목록, 생성, 중지, 등급과 분기 변경, 엔드포인트 선택, Liveshare 서버 상태, 소유자 ID, 서버가 보유한 감사 기록 및 두 Liveshare 서버 검사는 마운트된 네임스페이스의 메서드입니다. 소유자 페이지가 계속 호출하는 동일 출처 HTTP 경로는 로그인 왕복과 자격 증명 저장뿐입니다.

소유자는 조직 링크로 열람자의 접근을 허용합니다. 배포의 `LIVESHARE_ALLOWED_SUBJECTS`는 모든 공유를 제한하고 조직 링크 공유를 목록에 있는 주체로 좁힙니다. 저장된 `selected` 또는 `approval` 공유는 원래 ACL과 접근 요약을 유지하며 대화상자에서는 더 이상 생성하지 않습니다. `liveshareShares.create`는 해당 기록과 직접 Remote 호출자를 위해 `accessMode`와 `allowedSubjectIds`를 유지합니다. 공유 관리에는 저장된 링크, 등급, 가용성 및 Liveshare 서버의 감사 응답이 표시되며 공유의 등급 변경, 분기 스위치 전환 및 중지가 가능합니다. 실패한 작업은 오류로 계속 표시됩니다. UI는 클릭을 성공으로 간주하지 않고 소유자의 응답을 다시 읽습니다. 공유 대화상자에서 기존 공유도 편집합니다. 등급, 분기 스위치와 플러그인 엔드포인트를 선택해 스크롤 영역 밖의 저장 버튼 하나로 제출하고 소유자의 기록을 다시 읽습니다. 저장하지 않은 선택이 있으면 이를 표시하고, 닫으려 하면 선택이 버려진다고 먼저 경고합니다.

### 세션 등급

| 등급 | 열람자 작업 | 실행 제한 |
|---|---|---|
| `view` | 원본 세션에 프롬프트를 보내고 실행 중인 턴 중지 | 세션에 마운트되는 읽기 전용 샌드박스가 공유 열람자가 시작한 모든 턴에 적용됩니다. 해당 턴은 읽기 및 검색 기능(`read`, `read_image`, `glob`, `grep`, `present`)과 로컬 파일에 영향을 주지 않는 도구(`todo_write`, `skill`, `web_search`, `web_fetch`)를 사용할 수 있으며 호출이 선언한 모든 경로는 허용된 작업공간과 대조합니다 |
| `write` | 해당 작업공간의 파일도 수정 | 제한이 있는 쓰기 가능 샌드박스: 세션에서 열람자가 시작한 모든 턴에 보기 기능과 허용된 작업공간 안의 제한된 `edit`, `write`가 적용됩니다 |

두 등급 모두 공유 세션을 조작하며 쓰기 가능 여부가 다릅니다. 해당 세션에 대한 공유가 하나라도 활성화된 동안 샌드박스가 세션에 마운트되지만 공유 열람자가 시작하는 턴만 제한합니다. 소유자가 시작한 턴은 `bash`와 제한 없는 파일 시스템 도구를 포함해 세션 자체의 도구를 유지하며, 열람자 턴 중 소유자의 지시 입력은 그 턴과 함께 제한됩니다. 이 결정은 턴별로 호스트 메모리에만 보관되고 세션 로그에는 기록되지 않습니다. 모든 공유를 중지하거나 만료시키면 계층이 해제되고 세션 자체의 도구가 복원됩니다. 분기는 등급이 아닙니다. 공유에는 등급과 독립된 스위치가 있으며 허용된 열람자는 완료된 원본 접두부를 읽기 전용 한도 또는 공유가 `write` 등급일 때 제한된 쓰기 한도로 실행되는 자식으로 분기합니다.

첨부파일 업로드는 등급이나 분기 스위치에 속하지 않으며 표시 가능 여부에 따릅니다. 허용된 열람자는 공유 등급과 분기 허용 여부에 관계없이 공유 세션과 이 공유를 통해 만든 분기에 업로드한 파일을 첨부할 수 있습니다. 소유자에게 별도의 첨부 스위치는 없습니다.

어떤 등급도 세션 설정, 이름 변경, 보관, 작업공간 관리 또는 소유자의 전역 설정과 자격 증명을 허용하지 않습니다. 첨부파일 업로드는 표시 가능 여부에 따르며 등급 권한이 아닙니다. 소유자 게이트웨이는 열람자의 `settings/describe`, `credentials/describe`, `agentPresets/list`, `agentPresets/read`와 공유가 허용하지 않은 모든 엔드포인트를 Remote 실패 `remote-access/denied`(이유 `liveshare/read-only`)로 거부합니다. 설정 값, 자격 증명 참조 메타데이터와 프리셋 플러그인 설정은 열람자 데이터가 아닙니다. 열람자는 로컬 표시 기본값을 유지합니다. 이러한 관리 결정은 세션에 프롬프트를 보낼 권한과 별개입니다. **임시:** 이 페이지에 필요한 엔드포인트를 소유한 플러그인은 Typert 메타데이터의 엔드포인트별 접근 선언이 이 기능을 대체할 때까지 [`viewerDeclarationsOf(ctx)`](src/host/viewer-declarations.ts)로 이를 제공합니다. 변경하지 않는 엔드포인트에는 `registerViewerReadable(actions)`, 쓰는 엔드포인트에는 `registerViewerWritable(actions)`를 사용합니다. **제공 자체는 권한을 부여하지 않습니다.** 소유자가 공유별로 플러그인 엔드포인트를 노출하며, 공유는 플러그인의 현재 제공과 해당 공유의 선택에 모두 이름이 있는 엔드포인트만 열람자가 볼 수 있는 리소스에서 노출합니다. 쓰기 가능 선택은 공유 자체의 쓰기 규칙을 따르므로 **세션이 이미 쓰기를 허용하고 원본 실행이 제한된 공유에서만 적용되며, 어떤 제공이나 선택도 읽기 전용 공유를 쓰기 가능하게 만들지 않습니다.** 어느 종류든 이 정책이 이미 결정하는 `session/prompt`, `session/cancel`, `session/fork` 및 나머지 역할은 해당 모드의 결정에 맡깁니다. 소유자 자신의 페이지는 소유자 접근 기준으로 열리므로 화면이 바뀌지 않습니다.

소유자 게이트웨이는 호출이 지정한 세션과 작업공간을 기준으로 각 호출을 결정하고 대상이 없거나 유효하지 않으면 거부합니다. 열람자의 세션 목록과 작업공간 멤버십은 원본과 해당 열람자가 소유한 자식으로 제한됩니다. 페이지는 열람자의 접근 스냅샷에서 각 세션의 응답을 읽으므로 선택 변경 시 이전 세션의 권한이 넘어가지 않습니다. 알 수 없거나 읽을 수 없는 모드는 안전하게 거부합니다. 소유자는 원본과 자식 호출의 접근 허용을 다시 확인합니다. 권한 취소 시 관련 호출과 스트림이 취소되고, 허용 범위가 좁아진 공유는 공유 세션의 실행 중인 턴을 중지합니다. 페이지는 인증, 접근, 만료, 중지된 공유, 오프라인 소유자와 전송 실패를 구분하고 재시도 가능으로 분류된 실패만 재시도합니다.

<a id="understand-the-implementation"></a>
## 구현 이해하기

<details>
<summary>구현 내부 — 클릭하여 펼치기</summary>

열람자 페이지는 소유자 자신의 웹 셸입니다. Liveshare 서버는 `asset` 읽기로 소유자가 렌더링한 인덱스 문서를 가져오고 [viewer-carrier.ts](../liveshare-protocol/src/viewer-carrier.ts)의 캐리어 스크립트를 맨 앞에 배치합니다. 셸 에셋, 클라이언트 플러그인 번들 및 인덱스가 문서 기준 경로에서 참조하는 세 최상위 파일 `manifest.webmanifest`, `favicon.svg`, `favicon-dark.svg`는 같은 읽기를 통해 소유자의 프런트엔드 리더와 클라이언트 모듈 레지스트리에서 전달되므로 페이지는 모든 소유자 플러그인을 소유자의 버전으로 실행합니다. 모든 에셋 경로에서 소스 맵을 거부하며 이 검사가 기준입니다. Liveshare 서버를 거쳐 전달된 `asset` 읽기는 여기까지 읽히지 않은 상태로 도착하므로 서버의 같은 이름 규칙은 서버의 페이지 리소스 경로만 처리합니다. 제공되는 문서는 브라우저가 자격 증명 없이 가져올 수 있는 매니페스트 링크도 제거합니다. 캐리어는 Connection 호출과 Gateway 스트림을 `POST {base}/__share/rpc` 요청으로 변환하고 Liveshare 서버가 응답할 수 없는 읽기 전용 페이지 출처 소유자 경로 `/open-in-app/apps`와 `/api/present.host`를 서버 후단에 맡기지 않고 이 채널로 전달합니다. Liveshare 서버는 불투명한 본문 밖에서 인증된 행위자를 제공합니다. 소유자 읽기 핸들러는 공유와 열람자마다 하나의 Peer로 각 열람자의 호출과 스트림을 자체 Connection과 Gateway에 전달하며, 그 `share-viewer` 주체는 공유와 서버가 확인한 ID를 담습니다. Gateway는 이 패키지가 등록한 `share-viewer` 정책을 [`dsh-api-remote-access`](../../api/remote-access/README.md)에 적용해 Peer 호출과 전달할 세션 알림을 결정합니다. 제공받은 열람자는 공유 세션, 자신의 분기와 이를 보유한 작업공간에 대한 읽기 역할 및 공유 등급과 분기 스위치의 조건이 적용되는 분기와 쓰기 역할만 갖습니다. 첨부파일 업로드는 읽기 역할을 따릅니다. 읽기 핸들러는 공유 수명주기 거부, Liveshare 서버 권한 갱신, 콜드 세션 준비 및 분기 조정을 담당하고, 프롬프트나 중지를 준비하거나 전달하기 전에 정책의 쓰기 규칙을 읽으며, 권한이 끝나거나 공유가 중지·만료되거나 재검사에서 거부되면 열람자의 Peer를 해제합니다. 공유 원본 세션 준비는 열람자가 페이지를 요청하거나 스트림을 열 때도 시작되므로 해당 세션의 에이전트가 활성화되기 전에 재시작한 호스트도 조작에 필요한 작업을 얻습니다. 세션을 제한할 수 없는 공유는 읽기 전용이라는 사실 대신 그 상태를 표시합니다. 이 패키지의 브라우저 화면은 캐리어의 `__DSH_LIVESHARE_VIEWER__` 전역 변수가 있으면 열람자 화면을, 없으면 공유 작업을 마운트합니다. 제공되는 인덱스는 모든 인덱스가 소유자 기준으로 설정하는 전역 변수에 열람자 자신의 접근 스냅샷을 할당하고 페이지는 이후 열람자의 `remoteAccess/follow` 스냅샷을 따릅니다. CSS로 숨기는 것은 권한 부여가 아닙니다.

분기 요청은 행위자, 공유, 원본, 작업 ID와 완료된 접두부를 연결합니다. 영속 예약과 기록된 자식으로 이미 기록된 작업의 재시도는 같은 자식을 재사용합니다. 소유자의 `SessionForkRequest`가 자식 ID를 만들므로 자식 생성 후 기록 전에 중단된 요청은 다시 분기합니다. 레지스트리 변경은 비동기이며 잠금이 적용된 읽기·수정·쓰기와 원자적 게시가 끝난 뒤에만 완료됩니다. 호출자는 예약, 기록과 취소를 기다려야 합니다. 콜드 활성화는 Remote `session/prepare` 엔드포인트가 아닌 호스트의 일반 에이전트 조회와 대기 입력 실행 전 순차적인 `agent/created` 적용을 사용합니다. 자식 범위에는 안전하게 거부하는 가드 하나가 유지됩니다. 재연결은 적용 인스턴스를 교체하며 이전 인스턴스 해제가 후속 인스턴스를 제거할 수 없습니다.

열람자의 프롬프트는 해당 열람자를 지정하는 `source.principal`을 가진 `user-rpc` 메시지로 세션에 도착하고, 사전 단계는 모든 수신 메시지의 열람자를 모델에 도달하기 전에 Relay의 허용 정보와 다시 대조합니다. 실행은 턴별로 제한됩니다. 세션에 대한 공유가 활성화된 동안 허용된 입력이 공유 열람자를 지정하면 해당 턴은 호스트의 제한된 읽기·검색 기능(`read`, `read_image`, `glob`, `grep`, `present`), 로컬 파일에 영향을 주지 않는 도구(`todo_write`, `skill`, `web_search`, `web_fetch`), 그리고 일부 공유가 쓰기 가능할 때 제한된 `edit`와 `write`를 실행합니다. 다른 모든 도구는 해당 턴에서 거부되며 허용된 호출이 선언한 모든 경로는 해석되어 허용된 루트와 대조됩니다. 소유자가 시작한 턴은 마지막 공유가 중지되거나 만료될 때까지 세션 고유 도구를 유지합니다. 턴 결정은 호스트 메모리에만 있고 턴마다 다시 계산되며 세션 로그에 추가되지 않습니다. 각 작업은 공유의 현재 Relay 권한을 다시 읽고 해석된 대상을 허용 루트와 대조합니다. 열람자의 중지는 프롬프트처럼 Gateway를 통해 전달됩니다. 공유 등급이 확립되고 세션이 제한되어 있으면 `share-viewer` 정책이 허용하며, 소유자 자신의 세션 컨트롤러가 소유자가 시작한 턴을 포함해 현재 실행 중인 턴을 중지합니다. 읽기와 쓰기는 일반 쓰기 관찰 정책을 유지합니다. 실행 규칙은 [LiveShare 하위 시스템](../../../docs/subsystems/liveshare.md)을 참조하세요.

선택적 `share-access-state` 프레임과 인증된 요청 목록 응답은 완전하고 버전이 지정된 Liveshare 서버 권한을 제공합니다. 호스트는 소유자가 선택한 모드를 별도로 유지하고 실행에는 더 좁은 모드를 사용합니다. 관리 읽기를 포함한 모든 완전한 요청 목록 읽기에 같은 버전 및 세대 검사를 적용하며 권한이 없으면 접근 허용이 무효화됩니다. 권한 취소를 처음 발견한 요청은 `403 viewer-not-authorized`를 받고, 권한이 취소된 다른 작업은 중단됩니다. `share-viewer` 정책과 `agent/pre-step`은 수신 세션을 공유의 원본 또는 해당 행위자의 기록된 자식에 연결합니다. 대기 중인 외부 입력은 재시작 후에도 권한을 갱신하며 삭제된 공유는 복구된 Inbox 입력을 승인할 수 없습니다. 스냅샷 필드는 [공유 프로토콜 참조](../liveshare-protocol/README.md)를 확인하세요.

열람자 스트림은 이를 연 행위자에게 속합니다. 알림과 제어 프로젝션은 원본과 해당 행위자의 자식만 노출하며 대화형 승인과 질문은 호스트에 남습니다. `forkLineage`는 LiveShare 소유의 UI 프로젝션이며 권한이 아닙니다. 페이지가 프롬프트와 중지를 제공할지는 표시 계보와 무관하게 열람자의 접근 스냅샷에 있는 세션별 권한이 결정합니다.

외부 Liveshare 서버의 서비스, 저장소, OAuth 제공자와 배포는 별도로 소유됩니다. 소유자 전용 테스트는 여기에 있으며 두 완전한 제품을 시작하는 테스트는 상위 Liveshare 서버 통합에 남습니다.

<a id="model-experience"></a>
## 모델 경험

호스트가 열람자 프롬프트를 공유 세션으로 전달하는 방식으로 간접적으로 영향을 줍니다. 따라서 모델 요청에는 호스트가 해당 세션의 일반 사용자 입력으로 전달한 열람자 입력이 포함됩니다.

#### KV 캐시 영향

열람자 프롬프트는 일반 사용자 입력으로 공유 세션에 들어가므로 소유자 입력이 확장하는 것과 같은 캐시된 프롬프트 접두부를 확장합니다. 번들은 자체 요청 필드, 도구 또는 시스템 프롬프트 텍스트를 추가하지 않습니다.

## 알려진 제한과 미뤄진 작업

<a id="known-limitations-and-deferred-work"></a>

- 소유자, 열람자와 Liveshare 서버의 버전이 일치해야 합니다. 버전 간 호환성은 확립되지 않았습니다.
- 소유자는 허용된 열람자의 첨부파일 업로드를 거부할 수 없습니다. 세션을 읽을 수 있는 열람자는 등급 및 분기 스위치와 무관하게 파일도 첨부할 수 있습니다. 이는 수용된 위험입니다.
- 열람자 파일 작업은 허용된 루트에 대한 경로 검사로 제한되므로, 검사와 열기 사이에 로컬 프로세스가 허용 범위 안의 디렉터리를 심볼릭 링크로 바꾸면 작업을 다른 곳으로 보낼 수 있습니다. 디렉터리 핸들 기준 고정은 별도 변경으로 미뤄졌습니다. 열람자 도구는 제한된 읽기·검색 기능(`read`, `read_image`, `glob`, `grep`, `present`), 로컬 파일에 영향을 주지 않는 도구(`todo_write`, `skill`, `web_search`, `web_fetch`), 쓰기 등급에서의 제한된 `edit`와 `write`로 한정됩니다. `bash`, `pwsh`, `cua`, `plugin_manager`, `schedule_*` 도구와 이 기능에 명시되지 않은 모든 도구는 허용되지 않습니다.
- 열람자에게 별도 작업공간 파일 편집 화면이나 관리 권한은 없습니다.
- 엔드포인트 기능은 임시이며 검토 없이 신뢰됩니다. 레지스트리는 이름이 `<namespace>/<method>` Remote 엔드포인트인지만 확인하므로 선택된 엔드포인트는 인증된 모든 공유 열람자가 정책이 연결한 리소스에서 호출할 수 있으며, 열람자가 이를 통해 접근할 수 있는 범위를 제한하는 것은 엔드포인트 자체의 제한뿐입니다. 선택된 쓰기 가능 엔드포인트는 이미 쓰기를 허용하는 공유 안에서 파괴적인 작업을 할 수 있습니다. 기능은 `global`, `session`, `workspace` 리소스 종류만 포함하며 `event:` 이름은 거부됩니다.
- 소유자는 공유 패널에서 공유마다 노출 등급 하나를 선택합니다. 사용 불가, 읽기 전용, 쓰기 가능 중 하나이며 처음에는 사용 불가이고 엔드포인트를 선언하는 모든 플러그인에 적용됩니다. 관리자는 각 공유가 이미 노출하는 항목을 나열합니다. 저장 시 등급은 그때 플러그인이 선언한 엔드포인트로 확장되므로 저장 기록은 명시적 엔드포인트 목록으로 유지되고, 나중에 플러그인이 추가한 엔드포인트는 소유자가 다시 저장할 때까지 닫혀 있습니다. 현재 제공으로 채울 수 없는 등급은 선택할 수 없습니다. 어디에도 쓰기 가능 엔드포인트가 선언되지 않았다면 읽기 전용으로 낮추는 대신 쓰기 가능 등급을 사용할 수 없다고 표시합니다. 한 번의 저장은 공유의 등급, 분기 스위치, 엔드포인트를 이 순서로 기록합니다. 엔드포인트 기록이 거부되면 권한 기록은 유지하고 실패를 알리며 재시도할 소유자의 선택을 유지합니다. 선택은 공유 전체에 적용됩니다. 해당 공유에 허용된 모든 열람자는 정책이 연결한 리소스에서 선택된 엔드포인트를 호출할 수 있으며 열람자별 엔드포인트 수준은 확립되지 않았습니다. 제공 플러그인이 더 이상 선언하지 않는 선택은 아무것도 노출하지 않지만 소유자가 다시 저장할 때까지 기록에 남습니다. 완전한 등급이 아닌 기록은 사용 불가로 읽히고 저장 시 대체된다고 알립니다.
- 열람자가 볼 수 있는 세션을 더 이상 보유하지 않는 작업공간은 해당 작업공간 또는 작업공간 순서가 다음에 변경될 때에만 열람자의 작업공간 피드에서 빠집니다([원격 접근 제한](../../api/remote-access/README.md#known-limitations-and-deferred-work)).
- 레지스트리 파일 잠금은 동시 파일 쓰기로 영속 항목이 누락되는 것을 막지만 각 레지스트리는 자체 메모리 스냅샷을 읽습니다. 소유자 공유 상태 업데이트와 게이트웨이 소유권은 호스트 간에 조정되지 않으므로 홈마다 활성 소유자 호스트 하나를 사용하세요. 다중 호스트 권한 부여 서비스가 아닙니다.
- 별도의 런타임 불변 조건 동반 구성 요소는 게시되지 않습니다. 권한은 작업 자체에서 확인하며 이 패키지에는 별도 불변 조건 관찰자가 없습니다.
- 워커 재시작은 유지된 공유를 다시 등록하지만 열람자 스트림을 재생하지 않습니다. 열람자는 전송 계층을 통해 복구합니다. 등록 거부 401, 403, 410, 426은 다시 등록하는 일이 생길 때까지 해당 공유의 재연결 루프를 중지합니다. 재게시나 등급 변경, 해당 Liveshare 서버의 자격 증명 저장이 다시 등록하며 자격 증명 저장은 해당 주소에서 오프라인으로 남은 공유를 등록합니다. 복원은 이 호스트의 자체 만료 판독 결과와 관계없이 공유의 Liveshare 서버에 대해 보유한 자격 증명을 제시합니다. Liveshare 서버가 그 뒤에서 로그인을 갱신하고 자격 증명이 여전히 유효한지 서버만 결정하기 때문입니다. 같은 로컬 판독에서는 새 공유가 여전히 거부됩니다.
- 접근 모드는 `view` 접근을 허용하며 실제 분기·쓰기 권한은 공유 모드에서 나옵니다. 열람자별 실행 수준과 인스턴스 간 즉각적인 중지·취소 완료는 확립되지 않았습니다. 취소는 이미 확정된 쓰기를 되돌리지 못합니다. 쓰기에서 읽기 전용으로 바뀐 스냅샷은 이후 쓰기를 거부하지만 실행 중인 자식 턴의 즉각적인 취소를 보장하지 않습니다.
- 기능을 출시할 준비가 되려면 최종 조립 스냅샷 검증이 여전히 필요합니다.
- 열람자 페이지에서 Connection 캐리어를 우회하는 클라이언트 읽기(결과물 읽기, open-in-app, PDF 에셋, HMR 이벤트)는 소유자 대신 Liveshare 서버에 도달합니다. 인덱스 문서의 루트 절대 경로 매니페스트 및 아이콘 링크는 Liveshare 서버 접두부 아래에서 해석되지 않습니다.
